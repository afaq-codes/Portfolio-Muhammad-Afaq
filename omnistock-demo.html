The problem

Real profit was spread over four places.

A cash-on-delivery shop in Pakistan sells on Shopify, ships with TCS and PostEx, and buys traffic on Meta. Orders that come back to origin and courier COD payouts decide whether a month made money.

The owner is a friend, not a developer. His numbers sat in Shopify, two courier portals and Ads Manager. OmniStock puts them in one window on his own laptop, and it keeps working without internet.

What it does

From the shelf to the payout.

Warehouse

Racks and bins with a visual map, scan putaway, transfers, ABC cycle counts, and barcode and QR labels.

Pick lists by walking path

Picks are sorted by where the bins are, with scan-to-pick. Products show rack, on hand, reserved and available.

Shopify, many stores

Admin GraphQL API 2026-10. Polls orders every 2 minutes, reserves stock, pushes stock to every store, sends tracking back.

COD risk checks

A risk score from the phone number's history, a blacklist and a duplicate check before an order ships.

Couriers

TCS and PostEx: booking, tracking, airway bills that print offline, fuzzy city matching. 8 more adapters are in code, off by default.

Real profit

Meta Graph API ad spend set against delivered revenue, cost of goods, courier charges and returns. Real ROAS per campaign.

Insights

A live dashboard and 8 tabs, a pivot explorer with saved views, and a reorder planner. Charts in ECharts.

Offline first

Network jobs pause offline and resume on reconnect. Backups go to Google Drive. Alerts show in Windows and, if wanted, Telegram.

Kept from StockFlow

  • POS. Invoices, small receipts, discounts, F2 for a new sale.
  • Stock. Categories, suppliers, purchases and returns with restock.
  • Money. Payments, expenses and reports.
  • Backups. Export, import and scheduled local backups.

Shipping an online order turns it into a normal sale, so FIFO cost stays right. A return to origin puts the stock back.

AI assistant

Ask the shop a question.

The assistant uses the Claude Agent SDK on the local Claude Code login. It can read the shop's data but never change it.

12 read-only tools

Today's numbers, orders, low stock, bin locations, top products, customers, courier and ad results, schema and SQL.

Guarded SQL

Queries run in a separate worker. A guard lets through only SELECT and WITH.

Keys stay hidden

Account keys sit in Electron safeStorage and are never sent to the screen.

How it was built

Two days, planned contracts, then testing.

I built the OmniStock layer in about two days with Claude Code. I wrote the contracts between the feature areas first. Several subagents then worked on separate areas in parallel, and I integrated and tested the result.

The courier and Shopify logic came from RynoDesk, an earlier team project. I rewrote it as Node and Electron modules and fixed 10 bugs during the port.

Tested so far

  • Dev and production builds with 0 errors
  • A real Electron run of 16 screens with 0 console errors and 12 background jobs
  • Analytics at 20,000 test orders
  • A 27-check Shopify and orders integration test

Not live yet: Shopify, TCS, PostEx, Meta, Google Drive and Telegram have only run against simulated responses and sample payloads, not real accounts. PostEx was checked against its official guide. TCS fields are best effort, because its COD API docs need a login. The OmniStock installer has not been built yet.

The problem

Customer chats were spread over three apps.

A business gets messages on WhatsApp, Instagram and Messenger. Each one lives in its own app. Replies get missed, and nobody knows who is handling which chat.

RynoChat puts all three in one shared inbox. Each tenant connects its own channels. Chatbot flows answer the easy questions, then hand the chat to a person.

Web app

What I built on the web side.

Channels per tenant

WhatsApp Embedded Signup, Instagram Login and Facebook Pages, all on the Meta Graph API with webhook processing.

Shared inbox

One list for all three channels. Per-agent unread counts, pinned chats, labels, assign, resolve and reopen.

Chatbot flow builder

A visual builder in Angular with 9 step types, from questions and conditions to webhooks, an LLM step and handoff. The backend runs each flow per conversation.

One AI provider layer

Claude, Groq and Gemini behind one layer. WhatsApp voice notes are turned into text with Groq.

WhatsApp groups

Create and edit groups, share an invite link, approve or reject join requests, and manage participants.

Push to phones

Device tokens and Firebase Cloud Messaging. The server pushes new messages to the agent's phone.

Running it

Data retention, bulk delete, PDF export and an audit log. Actuator and Prometheus metrics, Docker and nginx.

Six UI languages

English, Arabic, German, Spanish, French and Urdu, including the login and password reset pages.

What's new

Plans with limits, and flows on more channels.

Since the last update to this page in October, nearly all the new work is mine: every UI commit and 6 of 7 backend commits.

  • 28 OctPricing plans with limits

    Each package sets how many channels and WhatsApp numbers a tenant may connect. The backend enforces it, and the package screens show the limits.

  • 28 OctAdvanced steps as a paid feature

    The LLM and Webhook steps need "Advanced Steps" in the tenant's package. A flow that uses them on a lower plan is rejected on save.

  • 30 OctOne flow on several channels

    A flow can now run on more than one channel. Old single-channel flows were moved over by a migration.

  • 30 OctFlows for chosen contacts

    A flow runs for all contacts, or only for a picked list.

  • FixesAcross the app

    Login and password reset in all 6 languages, chat labels, roles, contact and segment forms, inbox, routing rules and the agent performance report.

Flutter app

The same inbox on Android, built solo in two weeks.

Agents answer WhatsApp, Instagram and Messenger chats from their phone. Admins can also run contacts, campaigns, chatbots, users and reports. The app talks to the same Spring Boot backend, and I added the endpoints it needed: push tokens, pinned chats and WhatsApp groups.

Live inbox

Server-Sent Events keep it current. A banner shows when the link drops and reconnects.

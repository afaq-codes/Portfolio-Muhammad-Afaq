The problem

See work on staff laptops, openly, without card data leaving them.

Nixxe runs a call centre on its own CRM. The company wanted to know which staff laptops were active during a shift, keep regular screenshots, and open a live view when needed.

Two rules shaped the build. Staff must see a notice and agree before any capture starts. And the payment screens in the CRM must never reach the server as images or video.

How it works

One agent, one module, one admin area.

On the laptop

Electron tray agent

Starts on login and sits in the tray. Captures, redacts and uploads. An optional Windows service restarts it if it is killed.

On the server

Spring Boot module

Takes uploads over HTTPS with a device token, checked by its own auth filter. Two scheduled jobs raise alerts and clean up old data.

In the CRM

Angular admin area

Board, devices, screenshots, activity, alerts, audit and policy. Admins issue enrolment codes and shutdown tokens here.

The agent

What runs on each laptop.

Enrolment by code

The employee types a one-time code from the admin. The agent registers with a hashed machine ID and gets a device token.

Consent before capture

The company notice shows first. Nothing is captured until the employee clicks "I understand and acknowledge".

Screenshots on policy

The primary screen on the policy interval, only inside work hours unless the policy says otherwise.

Activity, not keystrokes

Idle time from Electron's powerMonitor, plus the foreground app and window title. Sent as 1-minute samples. No keystroke logging.

Live view and talk

Video over WebRTC, with a JPEG-frame fallback. Admins can talk back. The employee hears a chime and sees a bar with a mute button.

Payment redaction

The CRM sends the payment section's screen area to a local listener. The agent blacks it out on screenshots and video before upload.

Signed shutdown

The tray has no plain Quit. Pausing or removing it needs an admin-signed Ed25519 token for that one device.

Auto-update

electron-updater checks the backend's release folder, downloads in the background and installs on restart.

Admin screens

Run it from inside the CRM.

  • Board. A live tile per device with presence.
  • Devices. Create and send enrolment codes. Pause, resume, revoke, reassign or delete.
  • Screenshots. A gallery with secure image loading.
  • Activity. Per-employee and team usage, with productive, unproductive and neutral rules.
  • Alerts. Agent down, tamper, long idle, offline during shift. List and resolve.
  • Audit. Who viewed which screenshots or live sessions.
  • Policy. Interval, randomising, live view, activity, work hours, blur, retention and consent text.
  • Reminder banner. Shown to staff whose device has no running agent.

Privacy

Open with staff by design.

This is overt monitoring. Staff know the agent is there, and the limits are in the code.

Notice first

Versioned consent text, set in the policy.

Cards stay local

Redaction runs before upload, with sharp for images and canvas for video.

No keystrokes

Only idle time, app name and window title.

Viewers are logged

An audit trail of every screenshot and live session opened.

Talk is announced

A chime and an on-screen bar, with mute.

Data expires

Screenshots and samples are deleted after 45 days by default.
